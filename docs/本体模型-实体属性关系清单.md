# 数据开发本体 · 实体/属性/关系清单（平台手工创建用）

> 对应 OWL 文件 `docs/本体模型.owl`；平台不支持 TTL 导入，按本清单在界面上手工创建实体、属性、关系。
> 命名建议：实体/属性/关系用英文 id（如 `PlatformInstance`、`name`、`containsRule`），中文说明填在描述里。

## 一、实体（Classes）

### 定义层

| 实体 | 英文 id | 说明 | 上级（继承） |
|---|---|---|---|
| 平台分类 | PlatformCategory | 数据开发顶层分类（抽象） | — |
| 数据库脚本 | DataScriptPlatform | SQL 域（L1模型→L2生成平台→L3 .sql） | PlatformCategory |
| 数据ETL | DataETLPlatform | 加工域（多平台实例：FlashSync/BDS） | PlatformCategory |
| 数据调度 | DataSchedPlatform | 调度域 | PlatformCategory |
| 数据服务 | DataServicePlatform | SQL→API 消费域 | PlatformCategory |
| 平台实例 | PlatformInstance | 真实平台（低代码/高代码、格式/解析器不同） | — |
| 作业类型 | JobType | 平台实例自有的作业类型（如 传输任务/加工任务） | — |
| 作业 | Job | 具体作业（实例） | — |
| 作业目录 | Directory | 作业所在目录 | — |
| 治理目标 | Policy | 跨平台治理目标（如 设计开发一致性） | — |
| 规则 | Rule | 挂平台 + 属某 Policy（如 字段类型一致性） | — |
| 规则实现 | RuleImpl | 规则在特定作业类型上的实现 | — |

### 引用层（其他系统对象投影）

| 实体 | 英文 id | 说明 | 上级 |
|---|---|---|---|
| 数据模型 | Model | 建模平台模型投影（物理表名） | — |
| 模型版本 | ModelVersion | 模型版本链节点 | — |
| 模型增量 | ModelIncrement | 模型版本区间结构化增量 | — |
| 代码增量 | CodeIncrement | 作业代码增量 | — |
| 发布版本 | Release | DevOps 发布投影（最近发布即基线） | — |

### 实例层（运行产物）

| 实体 | 英文 id | 说明 | 上级 |
|---|---|---|---|
| 扫描运行 | ScanRun | 一次本体扫描（带本体版本快照） | — |
| 发现 | Finding | 命中的规则问题（回挂 Rule） | — |
| 解析轨迹 | ResolutionTrace | 前向处理过程四段 | — |

## 三、关系（Object Properties）

### 组织与分类

| 关系 | 英文 id | 来源 → 目标 | 基数 | 说明 |
|---|---|---|---|---|
| 分类包含实例 | hasPlatformInstance | PlatformCategory → PlatformInstance | 1:N | 四类分类下挂平台实例 |
| 实例归属分类 | platformOf | PlatformInstance → PlatformCategory | N:1 | （hasPlatformInstance 的逆） |
| 实例有作业类型 | hasJobType | PlatformInstance → JobType | 1:N | 平台实例下挂作业类型 |
| 作业类型属于实例 | definedBy | JobType → PlatformInstance | N:1 | （hasJobType 的逆） |
| 作业分类 | instanceOf | Job → JobType | N:1 | 作业属于哪个作业类型 |
| 作业在目录 | inDirectory | Job → Directory | N:1 | 作业树：目录→作业 |

### Policy / Rule / RuleImpl 三层

| 关系 | 英文 id | 来源 → 目标 | 基数 | 说明 |
|---|---|---|---|---|
| 策略含规则 | containsRule | Policy → Rule | 1:N | 治理目标聚合规则（**跨平台**） |
| 规则挂平台 | hasPlatform | Rule → PlatformCategory | N:1 | 规则的语义归属平台 |
| 规则有实现 | hasRuleImpl | Rule → RuleImpl | 1:N | 一个规则多实现 |
| 实现绑作业类型 | bindsJobType | RuleImpl → JobType | N:1 | 每个作业类型一个实现 |

### 引用层

| 关系 | 英文 id | 来源 → 目标 | 基数 | 说明 |
|---|---|---|---|---|
| 作业实现模型 | implements | Job → Model | N:1 | 物理表名匹配推导 |
| 模型有版本 | hasVersion | Model → ModelVersion | 1:N | 版本链 |
| 有增量 | hasIncrement | Model → ModelIncrement / Job → CodeIncrement | 1:N | 双侧增量 |
| 增量匹配 | matchesIncrement | CodeIncrement → ModelIncrement | N:1 | 四态（MATCH/AHEAD/BEHIND/DIVERGE） |
| 发布基线 | releaseBaseline | Release → Job | 1:N | 最近发布即一致性基线 |

### 实例层

| 关系 | 英文 id | 来源 → 目标 | 基数 | 说明 |
|---|---|---|---|---|
| 产生 | generatedBy | ScanRun → Job；Finding → ScanRun | | 溯源 |

## 四、示例实例（ABox，可选填入）

**平台/实例/作业类型**：
- 分类：数据库脚本 / 数据ETL / 数据调度 / 数据服务
- 实例：FlashSync(低代码) · BDS(高代码) · Dolphin(调度)
- 作业类型：FlashSync→传输任务/加工任务；BDS→加工任务；数据库脚本→(.sql)

**Policy/Rule/RuleImpl**：
- Policy：设计开发一致性（含 SQL+ETL 两条字段一致性 Rule）、脚本质量规范、SQL 安全规范
- Rule：字段类型一致性(挂数据ETL) → 两个 RuleImpl（bindsJobType 传输任务=flashsync-parser / 加工任务=bds-parser）
- RuleImpl：se-sql 1.8（数据库脚本）、fs-transfer 2.1（传输）、bds-etl 3.0（加工）

**引用层**：
- Model：M-1024(dwd_tax_payment, physicalTable=dwd_tax_payment, v3→v4)
- Release：REL-0820(commit b7d2f91, 基线)

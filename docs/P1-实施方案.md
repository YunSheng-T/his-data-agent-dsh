## 三、新建

### 1. `@his/workspace-repo` — 代码仓工作区插件
- 接**真实 git**（本地仓）：目录树走 `git ls-tree`，读文件走 `git show <branch>:<path>`，未提交态 = 工作区文件 + `git status`——**分支隔离语义天然由 git 保证**（feature 未合并的提交在 main 视图不可见），不自己造轮子。
- 文件类型契约解析：`.etl`（ETL 作业，Hive SQL / Python）与 `.dag`（调度作业 yaml：cron/依赖/重试/告警，`ref:` 指向 .etl）**分离管理、分离提交、分离审计**。
- 代码变更事件里附 AST 解析结果（字段映射、来源表），供 UI 双页签纯渲染。

### 2. `@his/domain-tools-dev` — 开发域工具包（14 个，risk 标注沿用 P0 约定）
| 工具 | 级别 | 说明 |
|---|---|---|
| `repo_checkout` / `job_read` / `ast_locate` | read | 定位与读取 |
| `lineage_upstream` / `lineage_downstream` | read | 血缘（修改链路的影响分析必过 `lineage_downstream`） |
| `etl_codegen` / `dag_gen` | workspace-write | codegen 输入 = hisModeling 里**已发布模型版本 + 标准引用**，代码注释逐列携带标准引用 |
| `code_lint` / `partition_check` / `danger_scan` | read | P1 用本地 SQL 解析实现 lint |
| `test_dryrun` | read（采样） | 只读账号、行数上限、超时熔断**固化在 Provider**；沙箱 seam 第一期接本地 DuckDB，生产换 Livy/网关时 Consumer 不动 |
| `git_add` / `git_commit` | commit 级（gated） | 人工闸门 1 |
| `sched_publish` | publish 级（gated） | 人工闸门 2 |

### 3. PTC 编排 —— ~~P1 第一穿刺点（M1）~~ **M1b 已穿刺通过：复用 dsh 原生 Code Mode**
- 挂载：his-data-agent 经 dsh-headless 开箱即有（`DSH_TOOLS_MODE=code`）；his-studio 在 patch 里 `- id: tools` `config.mode: code` + insert `code-runtime`（worker-thread）。
- 门禁语义保持：子调度逐个过审批管线，gated 工具在 `run_code` 程序内照常挂起等人。
- 编排不变量（lint 不过 → 不 gen dag；dry-run 不过 → 不进 commit 审批）写进 **系统提示词的旅程规约 + 域工具的返回结构**（lint 失败返回结构化阻塞原因，模型在程序里自然分支）；若实测模型不守约，再降级为固定编排代码兜底。
- `run_code` 标 read 级（riskOverrides），传输层本身自动放行，风险由子调度各自拦截。

### 4. 双可视化（studio-ui 前端增量）
- ETL 字段映射图：来源字段 → 目标字段逐列连线 + 转换徽标（NVL/CAST/IF）+ 标准引用标注；
- 调度依赖图：上游 → 本作业 → 下游，带触发时间与运行策略卡；
- 改代码即同步（数据源 = workspace-repo 的 AST 事件）。

### 5. `asset_sync` — 跨域联动（P1 只做单向）
- 上线时把「作业 → 模型」血缘回写资产目录（mock Provider 扩展）；建模空间模型发布页可见作业引用。

## 五、风险与对策

- **dsh developer preview 破坏性变更**：Definition 层保持薄，变动隔离在 Provider（沿用 P0 结构）。
- **codeRuntime 无模型侧入口**：退路为固定编排代码（可控性反而更强，token 优势保留）。
- **DuckDB 的 Node 绑定本机可用性**：先 `pnpm add duckdb` 试装；不行则 dry-run Provider 第一期用「mock + 行数上限/超时许诺」语义， seam 签名不变。
- **P0 回归被 P1 破坏**：验收条款 8 硬性要求，每个里程碑结束复跑 P0 断言（11/11 + 4/4 + studio e2e）。

## P1 边界（任务书明确不做）
不做 MR/PR 评审流；不做调度运维空间；不做模型变更 → ETL 反向提醒（P2）。

# HIS Data Agent · 技术架构

> 版本：commit 2a327e2（P0~P3 落地态）
> 读者：要在本仓上扩展能力的工程师。配套阅读《功能架构》。

## 1. 总体分层

```
┌────────────────────────────────────────────────────────┐
│ Consumer：大模型看到的 tool schema（name/parameters/    │
│           description），以及工作台 UI（studio-ui）      │
├────────────────────────────────────────────────────────┤
│ Definition 层：工具契约（接口 + JSON Schema + risk 标注）│
│   packages/domain-tools-modeling/definitions.js        │
│   packages/domain-tools-dev/definitions.js             │
├────────────────────────────────────────────────────────┤
│ Provider 层：平台能力的可替换替身（ seam ）              │
│   provider-mock / provider-git / provider-tenants /    │
│   provider-cicd / provider-sched / provider-dryrun     │
├────────────────────────────────────────────────────────┤
│ 装配层：Cordis 插件 + profile（cordis.patch.yml）       │
│   his-data-agent（headless 批跑）/ his-studio（工作台）  │
├────────────────────────────────────────────────────────┤
│ 基座：dsh 运行时（@deepseek-ai/dsh，Agent loop / 工具   │
│   调度 / 审批 / 会话日志 / AGENTS.md 注入 / PTC 代码模式）│
└────────────────────────────────────────────────────────┘
```

核心设计原则：**Seam 三层**。Definition 层先定稿、保持稳定（模型只认这层契约）；Provider 层是替身，联调真实平台时整层替换、Definition 一字不动。这是后续对接内网平台（建模平台 / GitLab / 真实 CICD / 调度平台）的架构保证。

## 3. 关键机制

### 3.1 Definition 契约（packages/*/definitions.js）

每个工具四要素：

```js
{
  name: 'etl_patch',
  risk: 'workspace-write',            // 审批策略唯一依据，词表见 §3.2
  description: '……（写给模型看的，直接影响调用质量）',
  parameters: { type: 'object', properties: {...}, required: [...] },
  output: { schema, render: (args, value) => [{ type: 'text', text: ... }] },
  execute: (args) => p.someProviderMethod(args),   // 只做转发，业务在模块/Provider
}
```

纪律：`execute` 里不写业务逻辑；业务逻辑在纯函数模块（ast/codegen/lint/lineage）或 Provider 方法里，便于单测与替换。

### 3.2 审批策略（approval-policy）

- 词表：`read` / `workspace-write`（自动执行）｜`commit` / `publish` / `knowledge-write`（抛审批点，人确认放行）｜未标注 **fail-closed** 按最高级拦截；
- 两层：`ctx.tools` 拦截器（按 risk 抛 ask）+ `ctx.tools.guard` 正则兜底（commit 的 diff 内容仍被扫描，模型绕过业务检查直接提交也过不了）；
- 内置工具（todo_write、run_code 等）用 profile 里的 `riskOverrides` 标注为 read；
- headless profile 挂自动应答器（旅程自动放行并落 `allowed-once` 日志）；studio 挂 UI 应答器（审批挂成 Promise，等前端 POST 回写）。

### 3.3 多租户仓与守卫（workspace-repo）

- `TenantRepoProvider` 门面：TENANTS 注册表（finance→数据仓 / risk→空仓）+ PACKAGE_REGISTRY 分包注册表（平台归属、是否接入）；
- **守卫在 Provider 层硬执行**（`writeWorking` 检查租户与分包，违例直接抛错）——UI 的半透明/toast 只是展示态；
- 单仓 → 多租户用 `renameSync` 原地迁移 + 幂等补种，历史分支全保留。

### 3.4 CICD（provider-cicd）

`LocalCicdProvider`：流水线号自增、规则集版本、`trigger/latestFor/verdictFor`；`scanEtlJob` 跑三类扫描（lint / 分区+危险 / 一致性=模型绑定↔代码@std 引用比对）。`repo_commit` 提交后同步触发并落报告，文件行扫描点与 `cicd_scan_report` 工具都从这里取数。换真实 CICD 时只需实现同名接口。

### 3.5 锚定（workspace-anchor）

用户在 UI 点击对象（模型/字段/文件/分支）→ 前端调 `/api/repo/...` 类接口 → 插件经 `agent/pre-step` 往会话注入一条 `source.form='notice'` 的合成消息（锚定摘要）。Agent 因此知道"当前上下文"而不必问。跨插件数据走 Cordis 服务（`ctx.provide('hisModeling', p)` / `inject`），不跨包 import。

### 3.6 会话行为调优（AGENTS.md）

dsh 自动把会话工作区根目录的 `AGENTS.md` 注入基线上下文。「动手优先、审批兜底、回复 ≤5 行、不提 git 字样、工具用法口径」都写在这里。**新会话生效**。要调整 Agent 的话术/流程习惯，优先改这里，不要动系统提示词插件。

## 4. 扩展指南：加一个新能力（以 ETL 检查为例）

假设要新增「ETL 慢查询模式检查」能力（`slow_scan`）：

**Step 1 · 写纯函数**（`packages/domain-tools-dev/lint.js` 或新建 `slowscan.js`）

```js
export function scanSlowPatterns(text, parsed) {
  // 纯函数：输入文本+AST，返回结构化问题清单。不碰 ctx、不碰 fs。
}
```

**Step 2 · 注册 Definition**（`packages/domain-tools-dev/definitions.js`）

```js
{
  name: 'slow_scan',
  risk: 'read',                        // 只读检查 → 免审批；若会改文件用 workspace-write
  description: '扫描 ETL 中的慢查询模式（笛卡尔积/未分区扫描/函数包裹分区列）（只读）',
  parameters: { type: 'object', properties: { job: S('string', ...) }, required: ['job'] },
  output: jsonOut,
  execute: (args) => p.scanSlow(args.job),   // p = 组合 Provider
}
```

然后在 `buildDevTools` 的 Provider 组合处把方法挂上（或直接在 execute 里调模块函数+repo 读文件）。

**Step 3 · 接 CICD（可选）**：若要让它成为流水线第四类扫描，在 `provider-cicd.js` 的 `scanEtlJob` 里加一段，结论并入权威报告——UI 扫描点、`cicd_scan_report` 自动生效，前端零改动。

**Step 4 · 写断言**（`tests/regression/assert-slowscan.mjs`，仿 assert-codegen 模式：构造样例 → 调纯函数/工具 → `check(label, ok)` → 汇总退出码）。旅程级行为再加日志断言（仿 assert-dev-journey 的结构化会话取样）。

**Step 5 · 教 Agent 用它（可选）**：AGENTS.md 加一行约定（何时调用、结果怎么解读）。description 写清楚通常就够。

**Step 6 · UI 呈现（可选）**：studio-ui/index.js 加 `/api/...` 路由（注入的服务已就位），public/index.html 加渲染。前端是单文件、每次请求现读，改完刷新即生效；后端 js 改动需重启 studio。

### 修改/生成类能力（如新的 etl_codegen 变体）

同样三步，但注意两条纪律：
- risk 至少 `workspace-write`；产物必须落 `repo.writeWorking`（租户/分包守卫会替你挡越界写入）；
- 若产物要进提交链路，无需动 repo_commit——它按分支 diff 全量暂存，新文件类型自动被 CICD 扫描覆盖（扫描规则按扩展名/目录在 scanEtlJob 里分支）。

### 换真实平台的替换点清单

| 现在的 Mock | 换成 | 不动的地方 |
|---|---|---|
| `domain-tools-modeling/provider-mock.js` | 建模平台 API（模型/标准/资产目录） | 12 个 Definition、UI、断言结构 |
| `workspace-repo/provider-git.js`（本地 git） | GitLab/GitHub API | 租户门面、四级地址、UI 仓树 |
| `domain-tools-dev/provider-cicd.js` | 真实 CICD 平台 | 扫描报告 schema、行级状态点 |
| `provider-sched.js` | 调度平台 API | 三重自检逻辑保留在前置 |
| `provider-dryrun.js` | 真实引擎（Spark/Hive） | 输出契约（含"模拟/真实"标注位） |

替换方式：profile 的 cordis.patch.yml 里给对应插件传 `config.provider = 新实现`（index.js 已留 `config.provider ??` 入口）。

## 5. 运行与调试

bash（macOS / Linux / Git Bash）：

```bash
# 工作台（常驻，:7300）
DSH_HOME="$PWD/dsh-home" DEEPSEEK_API_KEY=sk-*** dsh --profile his-studio

# headless 旅程（批跑，Code 模式必须显式 export DSH_TOOLS_MODE=code）
DSH_HOME="$PWD/dsh-home" DEEPSEEK_API_KEY=sk-*** DSH_TOOLS_MODE=code \
  dsh --profile his-data-agent "<指令>"

# 回归（zstd 需在 PATH 上）
cd tests/regression
for f in assert-*.mjs; do DSH_HOME="$PWD/../../dsh-home" node "$f"; done
```

PowerShell（Windows，逐行执行；环境变量先设再运行）：

```powershell
$env:DSH_HOME = "$PWD\dsh-home"; $env:DEEPSEEK_API_KEY = "sk-***"
dsh --profile his-studio                                    # 工作台
$env:DSH_TOOLS_MODE = "code"; dsh --profile his-data-agent "<指令>"   # 批跑旅程
cd tests\regression
Get-ChildItem assert-*.mjs | ForEach-Object { node $_.Name } # 回归
```

- studio 重启（杀端口进程）：bash `lsof -ti :7300 | xargs kill -9`；PowerShell `Get-NetTCPConnection -LocalPort 7300 | Select-Object -Expand OwningProcess | ForEach-Object { Stop-Process -Id $_ -Force }`；
- 会话日志：`dsh-home/sessions/<工作区路径编码>/session-*/session.jsonl.zstd`（zstd 解压后是 JSONL 事件流，断言脚本即分析它）；
- DeepSeek Key 只走环境变量，绝不落文件（.gitignore 已防）。

## 6. 回归体系（12 套，140+ 检查点）

| 脚本 | 覆盖 |
|---|---|
| assert-platform | 租户/分包/守卫/CICD/扫描（22） |
| assert-model-create | 新建模型全链（19） |
| assert-dev-tools | 开发域 17 工具（18） |
| assert-codegen | 生成/补丁/lint 规则（17） |
| assert-repo / assert-studio-repo | 仓 Provider / 工作台 API（17+18） |
| assert-gates / assert-impact | 审批门禁 / 反向联动（12+10） |
| assert-anchor | 锚定注入（5） |
| assert-journey / assert-dev-journey / assert-patch-journey | 真实模型旅程日志分析（11+9+13） |

旅程类断言的取样纪律：按**事件结构**（`tool/call`/`tool/code-dispatch` 的 `data.name`）识别旅程会话，不按 mtime 取最新（用户日常聊天会污染），不做 raw 字符串匹配（工具 schema 快照含工具名会误中）。

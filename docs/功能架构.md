# HIS Data Agent · 功能架构

> 版本：commit 2a327e2（P0~P3 落地态）
> 读者：汇报与产品对齐场景。技术细节见《技术架构》。

## 一句话定位

HIS Data Agent 是一个**数据工作台内置的 AI 数据工程师**：数据工程师/治理人员用自然语言下达指令，Agent 直接操作数据模型与 ETL 代码仓完成建模、开发、检查、提交、上线全链路；**所有写操作走分级审批门禁**，人始终握有关键闸门的确认权。

## 总体形态：两个空间 + 一个工作台

```
┌─────────────────────────────────────────────────────────┐
│  数据工作台（三栏：资产/仓树目录 · 工作区 · Data Agent 会话） │
├──────────────────────────┬──────────────────────────────┤
│  建模空间                 │  开发空间                     │
│  （.model 数据模型）       │  （ETL/调度代码仓，多租户）     │
│  · 模型目录/字段/版本      │  · 仓树（按平台分包）           │
│  · 数据标准绑定           │  · 分支管理                    │
│  · ER 关系图（AntV X6）   │  · 血缘视图                    │
│  · DDL 预览              │  · dry-run 试跑               │
│                          │  · CICD 扫描报告               │
└──────────────────────────┴──────────────────────────────┘
```

两个空间共享同一个 Data Agent（右侧会话栏），Agent 通过「锚定」感知用户正在看什么对象（哪个模型、哪个文件、哪个分支、哪个字段），回答和操作都贴着当前上下文走。

## 能力地图（29 个域工具）

### 建模空间（12 个工具）

| 类别 | 工具 | 说明 |
|------|------|------|
| 诊断（只读） | `model_read_fields` / `model_lint` / `std_ref_scan` / `std_search` | 读字段与绑定率、扫描未绑字段、匹配候选标准、检索标准库 |
| 创建 | `model_create` | **新建数据模型**：分层命名惯例（dim_/dwd_/…）、分区字段自动追加、字段可直绑标准 |
| 工作区修改 | `model_bind_std` / `model_alter_field` | 绑数据标准、改/加字段（未提交态，可反复改） |
| 版本化 | `model_commit` | 提交生成新版本（gated，需人确认） |
| 发布 | `ddl_gen` / `asset_register` / `lineage_attach` | 生成带标准注释的 DDL、发布为数据资产（gated）、登记血缘 |
| 标准治理 | `std_create_draft` | 起标准草案（gated，只到 draft 态，正式发布走人工审定） |

### 开发空间（17 个工具）

| 类别 | 工具 | 说明 |
|------|------|------|
| 定位（只读） | `repo_checkout` / `job_read` / `ast_locate` | 分支切换、读作业、列级 AST 定位 |
| 血缘（只读） | `lineage_upstream` / `lineage_downstream` / `impact_check` | 上游溯源、下游影响、变更影响分析 |
| 检查（只读） | `code_lint` / `partition_check` / `danger_scan` / `test_dryrun` | 规范检查、分区校验、危险模式扫描、模拟试跑 |
| 生成/修改 | `etl_codegen` / `dag_gen` / `etl_patch` | 从模型生成 ETL、生成调度 DAG、列级补丁（只动 .etl 不碰 .dag） |
| 提交上线 | `repo_commit` / `sched_publish` | 暂存+提交一体（gated，提交即触发 CICD）、调度上线（gated，工具层三重自检兜底） |
| 闭环 | `cicd_scan_report` / `asset_sync` | 读流水线权威扫描报告、血缘回写资产目录 |

## 平台化体系（V10–V12）

- **四级定位**：租户 → 代码仓 → 分支 → 分包，全地址形如 `tenant://finance/finance-dw@main/etl/dwd/xxx.etl`。顶栏租户下拉切换后目录/工作区/会话上下文全链路跟随；空租户有占位视图与切回引导。
- **分包注册表**：仓内目录按平台归属分组（etl/ → 主力 ETL 平台、dag/ → 调度平台、etl_legacy/ → 未接入的遗留平台，只读演示）。**守卫在服务端硬执行**：未接入分包不可写、非数据租户不可新建。
- **CICD 审批链**：`repo_commit` 提交即自动触发流水线，三类扫描并行——设计质量（lint）、SQL 安全（分区+危险模式）、一致性（模型绑定 ↔ 代码标准引用实时比对）；文件行级扫描状态点（✓/⚠）来自流水线权威报告；差异 → 修复 → 复扫清零形成闭环。审批链路中不出现 git 字样，全程「提交代码仓 / 流水线扫描」的数据化语言。

## 数据资产闭环（核心价值链）

```
新建模型 → 绑数据标准 → 提交版本 → 生成 DDL
   → 生成 ETL（列表达式自动携带 @标准引用注释）
   → 生成调度 DAG → lint/dry-run 自检 → 提交（CICD 三扫描）
   → 上线 → 血缘回写资产目录 → 模型页可见作业引用
```

反向联动：模型升版后，引用它的 ETL 作业在开发空间被自动标注「过期」提醒，形成治理 → 开发的双向闭环。

## 审批门禁（安全叙事）

五级风险词表，工具声明即策略：

| 级别 | 行为 | 例子 |
|------|------|------|
| read | 直接执行 | 读模型、lint、血缘 |
| workspace-write | 执行但留痕（未提交态） | 绑标准、etl_patch、model_create |
| commit / publish / knowledge-write | **拦截 → 人确认才放行** | repo_commit、sched_publish、asset_register、std_create_draft |
| 未标注 | fail-closed 按最高级拦截 | 任何新工具忘了标 risk 也安全 |

双层保险：审批层（人确认）+ 工具层自检（例如 lint 有 error 时 sched_publish 直接软拦，审批通过也不放行）。

## 已实证的端到端旅程

1. **新建链路**：新建 DWD 模型 → 生成 ETL+DAG → 提交上线，审批点恰好 2 次（提交+上线）；
2. **修改链路**：列级补丁修改逾期标识默认值，diff 只动 .etl 不动 .dag，影响分析先行；
3. **拦截链路**：无分区全量覆盖的危险作业被 lint error 拦截，publish 被工具层自检 blocked；
4. **扫描修复链路**：提交触发流水线 → 一致性差异 → 修复 → 复扫清零。

以上旅程均由真实大模型（DeepSeek）驱动跑通，并以 12 套回归断言（140+ 检查点）固化。
